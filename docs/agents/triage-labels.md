# 分诊标签约定

这些标签描述下一步处理方式。本文是协作约定，不证明远端已创建或应用任何标签。标签本身不授予代码、账号或发布权限。

| 标签 | 使用条件 | 离开该状态的证据 |
| --- | --- | --- |
| `needs-triage` | 问题尚未核实，范围或负责阶段未确定。 | 已核实触发条件、影响范围与目标阶段。 |
| `needs-info` | 缺少复现输入、环境、授权或验收条件。 | 缺失材料已补充，能够选择下一位处理者。 |
| `ready-for-agent` | 范围明确，前置依赖已满足，任务已授权。 | Agent 提供范围内的实现与可复测证据，或记录阻塞。 |
| `ready-for-human` | 等待用户决策、人工步骤、独立复审或最终授权。 | 负责者提供明确决定或完成所需步骤。 |
| `wontfix` | 负责者决定不实现该请求。 | Issue 记录理由、边界与可用替代方案。 |

通常选择一个主分诊标签。`needs-info` 须写明缺少什么，`ready-for-human` 须写明谁处理什么。`wontfix` 需要负责者的决定，不能用于掩盖失败。

## 暂停门禁

本约定使用 `paused` 标记显式暂停。任务规格中的暂停或阻塞指令即使没有远端标签也具有同样门禁。

暂停时停止实现、提交后的发布动作与账号操作，保存当前证据并向负责协调者报告。只有负责者明确解除暂停并重申范围后才能恢复。`ready-for-agent`、测试通过、CI 通过或时间经过都不能覆盖暂停。

独立复审待办、远端推送限制和阶段依赖另行保留。将标签切换为 `ready-for-agent` 不解锁 P1-2、P1-3 或 Phase 2、Phase 3。具体阶段见 [分期路线图](../ROADMAP.md)，交接要求见 [Issue 协作约定](issue-tracker.md)。

## SA-03 的待审状态

SA-03 交付本地 build-ready 文档和仓外离线证据，交给协调者安排独立复审。该交接不创建或修改远端标签，也不授权推送。

根 `AGENTS.md` 因常设禁令仍缺失。该缺口保留在交接记录中，不以标签或测试通过宣称仓库工作流完全补齐。
